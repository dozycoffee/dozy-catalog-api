# ADR-0004: 명세 원본을 저장소 docs/로 옮기고 Notion은 참고용으로 둔다

- **상태**: 채택
- **날짜**: 2026-09-18 (소급 작성)
- **관련**: 이슈 #26, PR #27, [문서 안내](../README.md)

## 맥락

명세(요구사항, 도메인 모델, ERD, 패키지 구조)의 원본은 Notion에 있었고, 로컬 `context/`(gitignore)에 에이전트 참고용 스냅샷을 두었다. 이 구조에서 세 가지 문제가 반복됐다.
- 두 벌을 손으로 맞추다 보니 문서와 코드가 계속 어긋났다. `storeScope` 표현, `Option.id`, 요구사항 2.6, 재고 추적 상품의 노출이 그 예다.
- 설계를 바꾸는 코드 PR에서 명세를 함께 리뷰할 수 없었다.
- `context/`가 추적되지 않아 git worktree에서는 명세가 보이지 않았다.

## 결정

- 프로젝트 공용 명세의 원본은 저장소 `docs/`다. 코드와 마찬가지로 PR로 고치고, 설계를 바꾸는 코드 PR에서 관련 문서를 함께 고친다.
- Notion Catalog 명세는 참고용 사본으로 둔다.
- `CLAUDE.md`는 커밋한다. 개인 에이전트 지침은 `CLAUDE.local.md`에, 로컬 전용 초안과 메모는 `context/`에 두고 둘 다 gitignore한다.
- 문서마다 한 가지 질문에만 답하고, 같은 내용을 두 문서에 적지 않는다([문서 안내](../README.md)).

## 검토한 대안

- **Notion 원본 + 로컬 스냅샷 유지(기존)**: 앞의 세 문제가 그대로 남는다.
- **문서 성격별로 원본을 나눔(기획 문서는 Notion, 개발 문서는 저장소)**: 원본 위치를 문서마다 기억해야 하고, 요구사항이 바뀔 때 두 곳을 오가야 한다.
- **모두 Notion 원본, 저장소는 읽기 전용 사본**: 코드 PR에서 설계 문서를 함께 바꿀 수 없어 어긋남이 계속된다.

## 결과

- **얻는 것**: 문서와 코드가 같은 PR에서 리뷰되고, 변경 이력이 git에 남으며, 어떤 worktree에서든 명세가 보인다.
- **감수하는 것**: 공개 저장소라 명세가 공개된다(비밀정보는 없음을 확인함). 기획 쪽 팀원도 Markdown과 PR로 작업해야 한다.
- **후속 작업**: Notion Catalog 명세 페이지에 "참고용 사본" 표시와 `docs/` 링크를 단다.
