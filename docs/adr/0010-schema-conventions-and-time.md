# ADR-0010: 스키마 기본 규칙과 시간 처리

- **상태**: 일부 대체됨 (동시 수정 → ADR-0013)
- **날짜**: 2026-09-19
- **관련**: 이슈 #45, [ERD](../erd.md), [영속성 규칙](../architecture/persistence.md), [도메인 모델](../domain-model.md#시간-처리), [요구사항](../requirements.md) 1.4

## 맥락

V1 스키마는 한 번 적용하면 고치지 않는다. 그래서 ID, 금액, 상태값, 시간, 동시 수정처럼 모든 테이블에 걸치는 규칙을 스키마를 만들기 전에 정해야 했다. 기존 ERD에는 도메인과 어긋난 곳(`DECIMAL` 금액과 도메인 `Money(Long)`)과, 정해지지 않은 곳("00시"가 어느 시간대인지)이 있었다.

## 결정

| 사안 | 결정 |
|---|---|
| ID | `BIGINT GENERATED ALWAYS AS IDENTITY`. DB가 만들고, 도메인은 `NewXxx` → 저장 후 ID를 받는다 |
| 금액 | `BIGINT`, 원 단위 정수. 도메인 `Money(Long)` 유지 |
| 상태값 | PostgreSQL ENUM 타입 대신 `VARCHAR` + `CHECK` |
| 시각 | `TIMESTAMPTZ` ↔ 도메인 `Instant` |
| 업무 날짜 | `DATE` ↔ 도메인 `LocalDate`. 업무 기준 시간대로 해석 |
| 동시 수정 | 애그리거트 루트 테이블에 `version`(낙관적 잠금) |
| 감사 컬럼 | `created_at`/`updated_at`은 DB 시계(`now()`)로 채운다. 트리거는 쓰지 않는다 |

**시간 처리**
- 업무 기준 시간대는 `Asia/Seoul`이다. `BusinessTimeZone` 인터페이스 뒤에 두고, 설정값(`catalog.business-zone`)으로 정한다.
- 코드는 시스템 기본 시간대(`ZoneId.systemDefault()`, 인자 없는 `LocalDate.now()`)를 쓰지 않는다. 현재 시각은 주입받은 `Clock`으로 구하고, 도메인은 `now`/`today`를 인자로 받는다.
- 서버, JVM, DB는 UTC로 고정한다. 이는 안전장치일 뿐이고, 코드의 정확성은 이 설정에 의존하지 않는다. 테스트 JVM 시간대도 UTC로 고정한다.
- SQL에서 날짜를 계산하지 않는다(`CURRENT_DATE`, `now()::date`). 날짜는 앱이 계산해 파라미터로 넘긴다.
- **예약 적용 시각**: 예약을 등록할 때 `effective_at` = "`effective_date`의 00시를 업무 시간대로 해석한 순간"을 계산해 저장한다. 배치는 `effective_at <= now`로만 대상을 고른다.
- **예약 적용일은 내일 이후만 허용한다.** 오늘 00시는 이미 지났으므로 오늘 적용은 즉시 반영으로 한다.

## 검토한 대안

- **도메인 `Money`를 BigDecimal로**: 원화에는 소수 단위가 없고, Catalog가 하는 계산은 정수 덧셈뿐이다(소수가 생기는 할인·세금 계산은 주문 쪽, ADR-0006). BigDecimal은 스케일에 따라 동등 비교가 달라지는 함정(`1.0 != 1.00`)만 늘린다.
- **PostgreSQL ENUM 타입(기존 ERD)**: R2DBC PostgreSQL 드라이버에 코덱을 등록해야 바인딩되고, Exposed에도 별도 컬럼 타입이 필요하며, 값 삭제·변경이 번거롭다.
- **`TIMESTAMP`(시간대 없음)**: 어느 시간대 기준인지 정보가 없어서, 서버나 세션 설정에 따라 해석이 달라진다.
- **`effective_date`만 저장하고 배치가 "업무 시간대 기준 오늘"과 비교**: 시간대 해석이 배치와 쿼리에 숨고, SQL 날짜 계산의 함정에 빠지기 쉽다. 여러 나라로 확장할 때 배치와 쿼리를 모두 고쳐야 한다.
- **Kotlin 날짜·시간 라이브러리(`kotlinx-datetime`)**: 이 서비스는 JVM 전용이라 멀티플랫폼 이점이 없다. 반면 Jackson 직렬화와 Spring 바인딩에 별도 설정이 필요하다. JDK 표준인 `java.time`을 쓴다.

## 결과

- **얻는 것**
  - 도메인과 스키마의 타입이 맞는다.
  - 서버 시간대와 무관하게 예약이 정확히 적용되고, 놓친 예약도 다음 배치에서 처리된다.
  - 여러 나라로 확장하면 등록할 때 쓰는 시간대만 바뀐다.
- **감수하는 것**: 상태값을 바꾸려면 `CHECK` 제약을 교체하는 마이그레이션이 필요하다.
- **재검토 조건**: 여러 나라나 여러 통화를 지원해야 하면 `Money`(통화 포함)와 업무 시간대(시장·매장별) 결정을 다시 본다. 이때 가격 책임 경계(ADR-0006)도 함께 본다.
