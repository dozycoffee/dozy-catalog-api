# ADR-0005: 진열 설정과 판매 가능 여부를 분리하고, 재고는 이벤트 투영으로 둔다

- **상태**: 채택
- **날짜**: 2026-09-18 (소급 작성)
- **관련**: 이슈 #25, PR #29, [요구사항](../requirements.md) 1.5, 2.1, 2.4, 2.5, 3장, [도메인 모델](../domain-model.md), [ERD](../erd.md)

## 맥락

요구사항이 바뀌었다. 재고 추적 상품도 활성화되면 바로 판매 목록에 나타나고, 매장 재고가 처음에는 0이라 품절로 표시된다. 그런데 기존 `StoreProductListing` 한 row에는 주인이 다른 값이 섞여 있었다.

| 값 | 주인 | 판매 범위에서 빠지면 |
|---|---|---|
| 노출·숨김, 진열 순서 | 점주 | 초기화 |
| 수동 품절 (재고 미추적 상품) | 점주 | 초기화 |
| 재고 품절 (재고 추적 상품) | 재고관리 서비스 | 유지해야 함 |

그래서 판매 범위에서 빠질 때 재고 상태까지 지워졌고, 매장이 다시 포함되면 재고가 있어도 품절로 보였다. 이름도 역할과 맞지 않았다("매장이 취급하는 상품 목록"처럼 읽히지만, 실제로는 기본값을 덮어쓰는 점주 설정이다).

## 결정

- `StoreDisplaySetting`: 점주의 진열 의도(노출·숨김, 진열 순서)만 담는다. 판매 범위에서 빠지면 삭제한다.
- `StoreProductAvailability`: 판매 가능 여부(판매중/품절)와 출처를 담는다.
  - `INVENTORY`(재고 추적 상품): 재고관리 서비스 이벤트로만 바뀐다. 기본값은 품절이다. 상품 상태나 판매 범위와 무관하게 항상 반영하고, 판매 범위에서 빠져도 지우지 않는다. `lastEventAt`보다 오래되었거나 같은 시각의 이벤트는 무시한다.
  - `OWNER`(재고 미추적 상품): 점주가 수동으로만 바꾼다. 기본값은 판매중이다. 판매 범위에서 빠지면 삭제한다.
- 재고 상태는 재고관리 서비스의 원본을 Catalog의 언어로 옮긴 로컬 투영이다. Catalog는 재고 수량을 모른다.

## 검토한 대안

- **재고 추적 상품의 품절만 따로 떼어 냄(`StoreInventoryStatus`)**: 범위는 작지만 "지금 살 수 있는가"라는 하나의 개념이 재고 추적 여부에 따라 두 곳에 나뉜다. 나중에 결국 다시 재구성해야 한다.
- **출처별로 타입을 나눔**: 노출 판단이 결국 두 저장소를 모두 봐야 해서 품절 개념을 한곳에 모으려던 목적이 사라진다.
- **판매 범위에서 빠질 때 재고 상태만 남기고 점주 값만 초기화**: 한 row 안에서 필드마다 수명이 달라져 규칙이 복잡해진다.
- **다시 포함될 때 재고관리 서비스에 재고를 조회**: 재동기화에는 필요하지만 기본 동기화 수단으로 쓰기엔 외부 API 의존이 크다.

## 결과

- **얻는 것**: 단종 중 폐기처럼 비활성 기간의 재고 변동도 반영되어 재판매 시점에 정확하다. 품절 규칙이 한 애그리거트에 모인다.
- **감수하는 것**: 이벤트 유실이나 장애가 생기면 투영이 어긋날 수 있다.
- **후속 작업**: 재고관리 서비스의 재고 일괄 조회 API가 확정되면, 재활성화·판매 범위 재포함 시점에 투영을 다시 맞춘다([미정 사항](../architecture/README.md#미정-사항)).
